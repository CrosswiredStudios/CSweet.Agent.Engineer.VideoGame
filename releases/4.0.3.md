# 4.0.3

Assigned development now reports local file-tool calls and shell commands as they start and return. Shell progress includes the real exit code, timeouts, and consecutive identical-command counts so ongoing validation and repeated failures are visible without treating model activity as completed work.

Final implementation edits are checkpointed before reading the completion report or evaluating validation results. A failed build or malformed report can block publication without leaving the retained workspace stuck at an older checkpoint.

Progress contains fixed operation labels and counters, never command arguments, file content, paths, or shell output. Reporting failures do not replay local work. Existing workspace confinement, shell policy, grants, and cancellation remain enforced.

Install the matching host progress-budget and Current Activity changes before upgrading the agent. Local telemetry is bounded to 500 operations with an explicit notice at the limit. Existing running instances retain their loaded code until a safe upgrade.
