# 4.2.0

Fixes the first half of a review loop seen at Super Awesome Games on 2026-11-10 (Prism Break ticket #22).

Adrian ran `check_browser_build` and it passed, but the receipt was bound to his published validations only when `BrowserSmokeCheck.Required` matched words such as "visible" or "canvas" in the acceptance criteria. #22's criteria had none. The model's `check_browser_build(...)` entry was then rejected by the publication boundary as tool notation, so it was dropped and the ticket published with only npm commands. The technical reviewer required the browser evidence from the plan's constraint text and rejected the ticket, although it approved the code.

- **The ticket's declaration decides.** When planning declares `Verifications` (contracts 5.4.0), browser evidence is required exactly when it contains `browser-smoke`, and a canvas exactly when that requirement says so. An explicit empty list means none. The text heuristics apply only to tickets without a declaration.
- **The model is told up front.** The assignment prompt states what the declaration requires and names the receipt (`node .csweet/browser-smoke.cjs <build directory>` plus `--canvas`) that the reviewer and QA check, and says not to commit screenshots or write extra verifiers.
- **A passing check is never lost.** A passing current-source `check_browser_build` receipt is bound to the published validations on every ticket, and tool-call notation is always replaced, so it can no longer fail the publication boundary on a ticket that doesn't require the check. Only a required check adds the failing "missing receipt" entry.
- The receipt command comes from `WorkItemVerificationKinds.BrowserSmokeReceiptCommand`, so the engineer and the reviewer agree on it.

Uses `CSweet.WorkManagement.Contracts` 5.4.0 (was 5.3.0). SDK unchanged.

Validation: not yet run. Written without a .NET SDK available; run `dotnet test` and the published output's `--self-test` before publishing. New tests in `BrowserSmokeCheckTests`.
